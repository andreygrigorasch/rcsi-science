# Использование ИИ

## 1. Инструменты и ключевые промпты

Использовал Codex для ревью исходного API, реализации и подготовки feature-тестов. Для проверки в сессии использовались PHP 8.4, PHPUnit, Laravel Pint, PostgreSQL 17 и локальный HTTP-сервер.

После первой реализации согласовали три запроса для повторной проверки. Ниже они приведены дословно.

> Сверь исходный `BookingController.php` с README. Разбери `store`, `destroy`, `index` и `today`. Для каждой проблемы укажи место в коде, сценарий воспроизведения, последствия, серьёзность и минимальное исправление. Проверь подстановку данных в SQL, определение владельца, часовые пояса и границы пересечения. Отдельно укажи подозрительные места, которые безопасны в текущем контексте. Сначала покажи выводы ревью.

> Опиши, какие условия должны быть истинны после создания брони. Интервал считаем полуоткрытым `[start, end)`, обе границы проверяем по местному времени офиса, а сравниваем и храним в UTC. Объясни, почему транзакции с обычной проверкой пересечения недостаточно при параллельных запросах. Сравни блокировку строки комнаты и ограничение на пересечение в PostgreSQL. Предложи вариант для текущего проекта и объясни, как он поведёт себя при пустом расписании и какие гарантии даёт для других путей записи.

> Запусти feature-тесты на PostgreSQL. Для проверки гонки отправь два одновременных HTTP-запроса от разных пользователей на один свободный слот. Подтверди, что оба дошли до базы, затем зафиксируй оба статуса и число строк после завершения запросов. Дай мне команды, чтобы я сам воспроизвёл соседние слоты и попытку отмены чужой брони. Для каждого запроса укажи ожидаемый результат, чтобы я мог сравнить его с фактическим.

## 2. Как перепроверили предложение ИИ

В сессии Codex проверили, достаточно ли одного вызова `DateTimeImmutable::createFromFormat` с шаблоном `!Y-m-d\TH:i:sP`.

| Вход | Результат на PHP 8.4 |
| --- | --- |
| `2026-02-30T10:00:00+03:00` | PHP вернул 2 марта. `DateTimeImmutable::getLastErrors()` показал предупреждение о несуществующей дате. |
| `2026-11-02T07:00Z` | PHP отклонил корректное время, потому что в строке опущены секунды. |

Поэтому перед разбором подставляем `00`, если секунды опущены, и отклоняем дату при предупреждении парсера. Feature-тесты покрывают эти случаи и проверяют компактную запись ISO 8601 со смещением.

## 3. Что проверили вручную и как подтвердили результат

Ручные проверки через HTTP и SQL выполнил Codex в этой сессии. Для вывода о гонке требовалось увидеть, что оба запроса конкурируют за блокировку, и сверить их ответы с числом строк в базе.

| Сценарий | Что подтвердили |
| --- | --- |
| Два пользователя бронируют один свободный слот | В `pg_stat_activity` оба запроса ждали блокировки строки комнаты. После её снятия получили `201` и `422`. В базе осталась одна запись. |
| Чужая и собственная отмена | Чужой токен получил `404`, владелец получил `204`. После отмены владельцем проверили, что запись удалена. |
| Ограничение на пересечение в PostgreSQL | В отдельной таблице с `EXCLUDE` база приняла соседние интервалы и отклонила прямую вставку пересекающейся брони. В приложении гарантия зависит от того, что все операции создания берут блокировку строки комнаты. |

`php artisan test --compact` на PostgreSQL 17 завершился успешно. Прошли 36 feature-тестов и 144 утверждения. Laravel Pint тоже прошёл.
