# Бронирование переговорных

API бронирования переговорных в Москве и Новосибирске на PHP 8.4, Laravel 13 и PostgreSQL 17.

[Запуск](#запуск) · [Тесты](#тесты) · [Ревью исходного кода](REVIEW.md) · [Использование ИИ](AI_NOTES.md)

## Запуск

Нужен Docker с Compose. Выполните из корня проекта при первом запуске.

```sh
env UID="$(id -u)" GID="$(id -g)" docker compose up -d --wait
docker compose exec app php artisan migrate --seed
```

Контейнер устанавливает зависимости при первом запуске. API доступно по адресу `http://localhost:8000/api`.

## Тесты

```sh
docker compose exec app php artisan test
```

Feature-тесты используют отдельную базу PostgreSQL `testing`. Они покрывают пересечения и соседние слоты, границы рабочего дня и длительности, сетку времени, эквивалентные смещения, ошибки ввода и права на отмену.

## Правила бронирования

- Интервалы одной комнаты не пересекаются. Бронь на 10:00–11:00 совместима с бронью на 11:00–12:00.
- Длительность составляет от 15 минут до 4 часов включительно. Начало и окончание должны попадать на сетку с шагом 15 минут.
- Бронь укладывается в 09:00–20:00 одного календарного дня по местному времени офиса. Допустимы прошедшие и будущие даты.
- Автор определяется по токену. Отменить бронь может только её автор.

## API

Передавайте `Authorization: Bearer <токен>` и `Accept: application/json`. Для JSON-запросов на создание укажите `Content-Type: application/json`.

| Метод | Адрес | Назначение |
| --- | --- | --- |
| GET | `/api/bookings` | Брони текущего пользователя |
| POST | `/api/bookings` | Создать бронь |
| DELETE | `/api/bookings/{id}` | Отменить бронь |
| GET | `/api/rooms/{room}/bookings/today` | Брони комнаты на сегодня |

Для создания нужны `room_id`, `title`, `starts_at` и `ends_at`. Обе границы передаются в календарном формате ISO 8601, например `2026-11-02T10:00:00+03:00` или `20261102T100000+0300`. Смещение обязательно (`Z`, `±HH:MM`, `±HHMM` или `±HH`). Секунды можно опустить. Ответ на создание содержит даты в UTC.

| Ситуация | Ответ |
| --- | --- |
| Бронь создана | `201` и объект брони |
| Некорректные поля, нарушение правил слота или занятая комната | `422` с `message` и `errors` по полям |
| Автор отменил бронь | `204` |
| Бронь отсутствует или принадлежит другому пользователю | `404` |

### Данные для локальной проверки

| Офис | Часовой пояс | Комнаты (ID) |
| --- | --- | --- |
| Москва | `Europe/Moscow` | Арбат (1), Тверская (2), Остоженка (3) |
| Новосибирск | `Asia/Novosibirsk` | Обь (4), Академгородок (5) |

Сидер создаёт двух демонстрационных пользователей с токенами `anna-token` и `boris-token`. Пример создаёт бронь в московской комнате Арбат.

```sh
curl -i -X POST http://localhost:8000/api/bookings \
  -H "Authorization: Bearer anna-token" \
  -H "Accept: application/json" \
  -H "Content-Type: application/json" \
  -d '{"room_id": 1, "title": "Планёрка", "starts_at": "2026-11-02T10:00:00+03:00", "ends_at": "2026-11-02T11:00:00+03:00"}'
```

## Защита от двойной брони

`store` в одной транзакции блокирует строку комнаты через `SELECT … FOR UPDATE`, проверяет пересечения и вставляет бронь. При `READ COMMITTED` второй запрос к этой комнате ждёт освобождения блокировки. Его следующий запрос видит бронь первого. Операции с разными комнатами используют разные строки. Любой дополнительный путь создания брони должен брать ту же блокировку. [Блокировки PostgreSQL](https://www.postgresql.org/docs/17/explicit-locking.html#LOCKING-ROWS) · [Read Committed](https://www.postgresql.org/docs/17/transaction-iso.html#XACT-READ-COMMITTED)

Границы новых броней сохраняются в UTC в существующих полях `timestamp`. Старые записи сравниваются по сохранённым значениям. Для восстановления потерянного смещения старой записи нужен первичный источник.
